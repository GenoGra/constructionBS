Run di benchmark: le combinazioni da sviluppare per ogni tool

Enumerazione esplicita, run per run, del set benchmark definito nello studio unificato delle flag. Non il cielo teorico delle combinazioni (N_disc), ma le configurazioni concrete che vale la pena eseguire — con i valori esatti dei flag per ciascuna.

Cos'è questo documento. Lo studio delle flag conta, per ogni tool, tre spazi: N_qual (modalità strutturali), N_disc (con le continue discretizzate in 3 regimi — il cielo teorico) e Benchmark (il sottoinsieme eseguibile). Qui prendiamo solo l'ultimo e lo apriamo: ogni riga è una run reale con la riga di comando corrispondente. Le celle evidenziate sono i flag che deviano dalla baseline; il resto resta al default. La riga baseline è la configurazione di partenza. Totale: 48 run sugli 8 tool. I valori dei regimi provengono dallo studio delle flag verificato contro le repo alle versioni pinnate.

Come leggere il rapporto N_disc → RunIl salto da decine di migliaia di combinazioni teoriche a ~48 run è dovuto a tre mosse: (1) compressione agli estremi per gli assi mode/switch (Cactus, POASTA); (2) OFAT invece di pieno-fattoriale dove lo spazio esplode (PGGB); (3) fissaggio al default degli assi non prioritari (Theseus, i gg-* di Minigraph). Dove lo spazio è già piccolo (LCPan) il benchmark coincide col pieno.
