ConstructionBS · Pangenome tooling · requisiti minimi

Flag obbligatorie: cosa serve o il tool non costruisce

Per ogni tool, il set minimo di argomenti senza cui la costruzione non avviene. Non gli assi da variare (quelli sono negli altri studi): qui solo ciò che è non negoziabile per ottenere un grafo.

Due livelli di "obbligatorio". Ho distinto ciò che ferma l'esecuzione da ciò che ferma il grafo, perché diversi tool partono lo stesso ma non emettono un grafo utilizzabile.
esecuzione senza questo il tool non parte (errore / usage / exit≠0) grafo il tool parte ma non produce un grafo (o non uno interoperabile) precondizione non è un flag: un file/stato richiesto a monte

Fonte. Ogni requisito è verificato contro il binario/wrapper alla versione pinnata (usage line, validazione del parser o del wrapper, sorgente) e contro l'invocazione reale del repo (utils/tool_commands.py o docs/runbook_commands.md). L'output va quasi sempre su stdout: dove indicato, il redirect > è esso stesso obbligatorio per persistere il grafo.

Minigraph lh3/minigraph · v0.21

Con soli input positional (senza -x ggs) minigraph fa mapping, non costruzione: emette GAF, non un GFA. Il preset è ciò che lo mette in modalità "costruisci".

minigraph -cxggs <ref.fa> <query.fa> [query2.fa …] > out.gfa # -c raccomandato ma opzionale
ArgomentoLivelloPerché è obbligatorioFonte
-x ggs / --ggenesecuzione modeSenza, minigraph resta in modalità mapping (-x lr) e produce allineamenti GAF, non un grafo. --ggen è l'interruttore reale; ggs è il preset raccomandato (setta anche i default graph-gen)usage + test
<ref> (1° positional)esecuzione inputSenza argomenti il tool stampa l'usage ed esce con codice 1: non parteusage + test (exit 1)
<query> (≥1 positional)grafo inputCon il solo reference emette le sue S-line e si ferma: nessun assembly viene aggiunto → non è un pangenoma. Serve almeno un'assembly-query per costruiretest (no ggen_map)
> out.gfaesecuzione outputIl GFA va su stdout; senza redirect (o -o FILE) il grafo non viene persistitousage
-cracc.Non obbligatorio. Ometterlo stampa solo un warning e costruisce comunque un GFA valido; migliora la precisione degli inserti. Il repo lo passa (-cxggs)test (exit 0)

Theseus theseus-lib · v1.0.0

Costruzione via theseus_msa. -s/-f sono [Required]; -t 1 non è richiesto dal parser ma senza di esso l'output è un MSA, non un grafo.

theseus_msa -s <input.fa> -f <output.gfa> -t 1
ArgomentoLivelloPerché è obbligatorioFonte
-s, --sequencesesecuzione inputOmetterlo → Missing required arguments + usage, non parteusage [Required] + test
-f, --outputesecuzione outputOmetterlo → Missing required arguments, rifiuta di eseguireusage [Required] + test
-t 1, --output_typegrafo output-typeIl parser NON lo richiede (gira a exit 0), ma il default è 0=MSA: senza -t 1 l'output è un allineamento multiplo FASTA-like, non un GFA. Per costruire un grafo è di fatto obbligatoriousage (default 0) + test + repo
-m / -x / -o / -e / -lopz.Non obbligatori: scoring con default (0/2/3/1) e lag_pruning opzionaleusage
Nel repo — runbook-onlyTheseus non è nell'orchestratore per scelta. Runbook: theseus_msa -s /{PAN_INPUT} -f /{OUTPUT_DIR}/theseus_{DS}.gfa -t 1. Il commento del runbook nota che -t 1 seleziona l'output GFA e che -t è il formato, non un conteggio thread (Theseus è single-thread). La patch P/W-lines in patches/theseus/ è tenuta ma non applicata → GFA POA vanilla.

vg vgteam/vg · v1.71.0

-v, --vcfgrafo inputNon richiesto per partire, ma senza il grafo è solo il reference lineare: per un pangenoma (grafo di variazione) le varianti del VCF vanno incluse con -vhelp + repo
